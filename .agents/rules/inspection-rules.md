# 홈페이지 점검 공통 규칙

## 기본 원칙

- 점검 대상 홈페이지를 읽기 전용으로 탐색한다.
- 로그인, 게시물 작성, 개인정보 입력, 파일 업로드, 수정 및 삭제를 하지 않는다.
- 오류라고 확정할 근거가 부족하면 `담당자 확인 필요`로 분류한다.
- 과거 게시물이라는 이유만으로 현행화 오류로 분류하지 않는다.
- 모든 지적사항에는 페이지 제목, URL, 발견 내용, 판단 근거를 기록한다.
- 접속 오류와 파일 다운로드 오류는 최소 2회 재확인한다.
- 동일 URL은 원칙적으로 한 번만 점검한다.
- 쿼리스트링과 앵커만 다른 동일 콘텐츠는 중복으로 간주할 수 있다.
- 점검하지 못한 페이지와 사유를 반드시 기록한다.

## 토큰 절감 원칙

- 페이지 전체 텍스트나 HTML을 그대로 읽지 않는다.
- `webcheck` MCP 서버 (webcheck-mcp, `mcp-server/`)가 연결되어 있으면 링크 상태 확인(`check_links`)과 게시일 판정(`check_recency`)은 그 서버에 맡긴다. 페이지를 브라우저로 열어 확인하는 것은 MCP로 처리 못 하는 항목(맥락 판단, 셀렉터 미확보 게시판 등)으로 한정한다.
- MCP 서버가 없을 때만 목록형 콘텐츠를 스크립트 실행(JS 평가)으로 제목·URL·게시일 등 필요한 필드만 추출하여 확인한다.
  - 예: `document.querySelector('.board_list tbody tr:first-child .date').innerText`
- 같은 도메인의 여러 목록 페이지는 가능하면 한 번의 요청으로 모아서 확인하고, 페이지마다 별도로 브라우저를 열지 않는다.
- 게시일 확인이 목적이면 목록 페이지 전체를 순회하지 않고 첫 화면의 최신 글 한 건만 확인한다.
- 페이지 전문 확인이 반드시 필요한 경우(오류 재현, 문구 검토 등)에 한해서만 본문을 읽는다.
- `references/page-cache.md`에 기록된 추출 방법(셀렉터 등)이 있으면 재탐색 없이 그대로 사용한다.
- 날짜 차이(3개월 경과 여부) 계산은 암산이나 추정에 의존하지 않고, 스크립트 또는 명시적 계산식으로 검증한다.

## HTTP 상태코드만으로 오류를 확정하지 않는다

- 대표 홈페이지 CMS는 존재하지 않는 경로도 **HTTP 200**으로 응답하고 본문에 커스텀 에러 이미지("요청하신 파일이나 경로는 존재하지 않습니다")만 표시하는 것으로 확인되었다 (2026-09-15 검증).
- 따라서 링크 확인 시 상태코드가 200이어도 본문에 알려진 에러 문구가 있는지 함께 확인한다. `check_links` MCP 도구는 이를 자동으로 검사한다.
- 반대로 상태코드가 200이 아니더라도 정상적인 리다이렉트일 수 있으므로, 최종 응답 상태와 본문을 함께 본다.

## 결과 분류

1. 확정 오류
2. 게시 최신성 지연
3. 현행화 의심
4. 문구 개선
5. 담당자 확인 필요
6. 정상

## 중요도

- 긴급: 대국민 서비스 이용 불가, 개인정보 노출 가능성, 주요 메뉴 전체 장애
- 높음: 404/500, 첨부파일 실패, 최신 콘텐츠 3개월 초과, 잘못된 연락처 가능성
- 보통: 문구 오류, 부분 이미지 오류, 일부 링크 이상
- 낮음: 표현 개선, 경미한 표기 불일치

## 확정 오류 기준

- HTTP 404 또는 500 오류
- 페이지가 반복해서 열리지 않음
- 이미지가 깨져 표시됨
- 링크와 연결 대상이 명백히 다름
- 첨부파일 다운로드 실패
- 주요 기능이 반복적으로 작동하지 않음

## 게시 최신성 점검 원칙

- 게시판, 카드형 목록, 썸네일 목록, 공지 목록, 보도자료 목록, 행사 목록 등 게시일이 표시되는 콘텐츠 영역을 점검한다.
- 각 콘텐츠 영역의 목록 첫 화면에서 가장 최신 글의 게시일을 찾는다.
- 현재 날짜와 최신 게시일의 차이를 계산한다.
- 차이가 3개월 이상이면 `게시 최신성 지연`으로 분류한다.
- 정확히 3개월 전 날짜도 `3개월 이상`으로 본다.
- 월 단위 계산은 단순 90일이 아니라 달력 기준 3개월을 우선 적용한다.
- 게시일이 여러 종류인 경우 `게시일`, `등록일`, `작성일`, `등록일자`를 우선한다.
- `수정일`, `조회일`, `행사일`, `마감일`만 있는 경우 게시일로 단정하지 않는다.
- 최신 글이 상단 고정 게시물이라면 실제 등록일을 확인하고, 고정 여부를 기록한다.
- 공지사항처럼 비정기 게시가 정상일 수 있는 영역은 바로 오류로 확정하지 않고 `담당자 확인 필요`로 병기할 수 있다.
- 게시일이 보이지 않으면 `게시일 확인 불가`로 기록한다.
- `check_recency` MCP 도구는 범용 명칭(`최신성 지연`, `날짜 확인 불가` 등)을 반환한다. 보고서에는 이 프로젝트의 명칭(`게시 최신성 지연`, `게시일 확인 불가`)으로 치환해서 기록한다. 매핑표는 `mcp-server/README.md` 참고.

## 오류로 보지 않는 항목

- 과거 보도자료 및 연구성과 자료 자체
- 기록 보존 목적의 과거 행사 페이지
- 종료된 공고를 아카이브로 보존한 경우
- 법령·지침 구버전 게시물
- 게시 빈도가 원래 낮은 연례 간행물
