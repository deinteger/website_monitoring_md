# 증분 점검 (Incremental Inspection)

매번 전체 페이지를 다시 탐색하는 대신, 이전 점검 결과와 비교하여 변화가 있는 게시판만 상세 점검한다.
토큰 사용량과 점검 시간을 대폭 절감할 수 있다.

## 전제 조건

- `references/page-cache.md`에 이전 점검의 게시판별 최신게시일이 기록되어 있어야 한다.
- 첫 번째 점검은 반드시 `homepage-full-inspection.md` 또는 `homepage-test-inspection.md`로 수행한다.

## 점검 주기 기준

오늘 날짜 기준으로 아래 조건에 해당하는 게시판만 점검 대상에 포함한다.

| 점검주기 | 포함 조건 |
| --- | --- |
| 매일 | 점검주기가 `매일`인 항목은 항상 포함 |
| 주1회 | 마지막점검일로부터 7일 이상 경과한 항목 |
| 분기1회 | 마지막점검일로부터 90일 이상 경과한 항목 |
| 월1회 | 마지막점검일로부터 30일 이상 경과한 항목 |

## 증분 점검 절차

1. `references/page-cache.md`를 읽어 오늘 점검 대상 게시판 목록을 확인한다.
   - 각 행의 `점검주기`와 `마지막점검일`을 기준으로 오늘 점검 여부를 판단한다.
2. 점검 대상 게시판의 목록 첫 페이지에 접속하여 **최신 게시일만 확인**한다.
   - `추출셀렉터`가 캐시에 있으면 페이지 전문을 읽지 않고 해당 셀렉터로 값만 추출한다.
   - 없으면 이번 점검에서 찾은 셀렉터를 `추출셀렉터`에 기록한다.
3. 캐시의 `최신게시일`과 오늘 확인한 날짜를 비교한다.
   - **같으면**: 변화 없음 → 스킵. `마지막점검일`만 오늘 날짜로 업데이트한다.
   - **다르면(새 글 있음)**: 해당 게시판을 상세 점검 대상에 추가한다.
4. 상세 점검 대상 게시판에 대해서만 전체 점검 항목(링크 오류, 이미지, 문구 등)을 수행한다.
5. 점검 후 `references/page-cache.md`의 해당 행을 업데이트한다.
   - `최신게시일` ← 오늘 확인한 최신 게시일
   - `마지막점검일` ← 오늘 날짜
   - `판정` ← 오늘 판정 결과
6. 결과를 `output/YYYY-MM-DD/` 폴더에 작성한다.
   - 변화 없는 게시판은 recency-status.csv에 캐시 값을 그대로 기재하고 비고에 `캐시 (변화없음)`으로 표시한다.
   - 새 글이 감지된 게시판만 상세 항목을 inspection-details.csv에 기록한다.

## 출력 결과

- `output/YYYY-MM-DD/inspection-summary.md` (변화 감지된 항목 중심으로 작성)
- `output/YYYY-MM-DD/inspection-details.csv` (변화 감지된 게시판의 오류 항목)
- `output/YYYY-MM-DD/recency-status.csv` (전체 게시판 현황, 스킵 항목은 캐시 값 사용)
- `references/page-cache.md` (점검 후 자동 업데이트)

## 주의 사항

- 정적 페이지(기관소개, 조직도, 찾아오시는길 등)는 `월1회` 주기로 설정하고 page-cache.md에 추가한다.
- 게시 최신성 지연으로 이미 판정된 게시판도 새 글이 올라오면 즉시 감지된다.
- 캐시에 없는 신규 게시판이 발견되면 page-cache.md에 행을 추가하고 즉시 점검한다.
