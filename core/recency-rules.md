# 게시 최신성 판단 기준

## 기본 기준

- 점검 대상: 게시일이 표시되는 게시판, 카드, 썸네일, 공지, 보도자료, 행사, 자료실 등
- 판단 대상 날짜: 목록에서 가장 최신 글의 게시일
- 기준일: 점검 실행일 (`--today`로 지정 가능)
- 지연 기준: 최신 게시일이 기준일의 달력 기준 3개월 전 날짜와 **같거나 이전**인 경우 (`settings.json`의 `stale_months`로 조정)
- 경계값: 정확히 3개월 전도 지연으로 판정

**계산은 `scripts/monlib.py`(`add_months`, `is_stale`)가 한다.** 에이전트는 날짜를 직접 계산하지 않는다.
말일은 해당 월 말일로 보정한다 (예: 기준일 5월 31일의 3개월 전 = 2월 28일).

## 날짜 우선순위

1. 게시일
2. 등록일
3. 작성일
4. 등록일자

다음 날짜만 있는 경우 게시일로 단정하지 않는다.

- 수정일
- 조회일
- 행사일
- 접수 마감일
- 첨부파일 생성일

스크립트는 기본적으로 **각 행의 첫 번째 날짜**를 게시일로 본다 (`date_source`). 게시일이 첫 열이 아닌 사이트는 `site-profile.json`에서
`row_tag`/`date_regex`/`date_source`로 보정한다. 날짜 의미가 불명확하면 `core/judgement-guide.md` 8절의 `future_date` 처리를 따른다.

## 판정 예시

기준일이 2026-07-30인 경우:

- 3개월 기준일: 2026-04-30
- 최신 게시일 2026-05-01: 정상
- 최신 게시일 2026-04-30: 게시 최신성 지연
- 최신 게시일 2026-04-29: 게시 최신성 지연

## 점검 주기와의 관계

- 증분 점검에서 방문하지 않은 게시판도 **캐시된 최신 게시일과 오늘 날짜로 판정을 매번 다시 계산**한다 (게시판이 바뀌지 않아도 시간이 지나면 지연이 되기 때문).
- 시간 경과로 오늘 새로 지연이 되는 게시판은 1회 방문해 재확인한다.
- 점검 주기 `monthly`/`quarterly`도 달력 기준(1개월/3개월)이다. 90일 같은 일수 환산을 쓰지 않는다.

## 예외 처리

- 상단 고정글은 고정 여부를 기록하고 실제 최신 등록글을 추가 확인한다 (스크립트는 행 중 가장 최근 날짜를 사용).
- 연례 발간물처럼 게시 빈도가 낮은 콘텐츠는 `irregular`로 지정해 `담당자 확인 필요`를 병기한다.
- 콘텐츠 영역 자체가 종료되었거나 아카이브인 경우 `recency_exempt`로 지정한다.
- 목록 첫 화면이 날짜순이 아닌 경우 정렬 기준을 확인한다.
- 게시일이 보이지 않으면 `게시일 확인 불가`로 기록한다.
- 날짜 형식이 불명확하면 원문을 그대로 기록하고 판단을 유보한다.
