# 홈페이지 점검 공통 규칙

모든 점검(에이전트·스크립트·API 러너)이 지키는 규칙의 **단일 원본**이다. 다른 문서는 이 파일을 참조만 한다.

## 1. 안전 원칙 (예외 없음)

- 점검 대상은 **읽기 전용**으로만 접근한다 (GET/HEAD 요청, 브라우저 열람).
- 로그인, 게시물 등록·수정·삭제, 개인정보 입력, 파일 업로드, 관리자 기능 접근을 하지 않는다.
- 허용 도메인(`site-profile.json`의 `allowed_domains`) 밖의 사이트는 접속하지 않고 URL만 기록한다.
- 차단 의심(403/429 연속)이 발생하면 **즉시 중단**하고 재시도하지 않는다. 우회(주소·헤더 변경, 요청 증가)를 하지 않는다.
- 요청 정책(동시 요청 수, 요청 간격, User-Agent)을 임의로 완화하지 않는다. 변경은 보안·운영 부서 협의 후 `settings.json`에서 한다.
- 점검 내용을 외부 AI 서비스로 보내려면 기관 보안 승인 후 `settings.json`의 `llm.allowed`를 명시해야 한다.
- 개인정보(주민번호·전화·이메일)는 결과 파일과 AI 입력에서 마스킹한다. 점검 결과에 개인정보 원문을 옮겨 적지 않는다.
- 담당자 연락처 조회(`lookup.py contact`)는 해당 페이지에 **공개된 표기만** 전달하고 추정·생성하지 않으며, 결과를 저장하거나 다른 곳에 옮기지 않는다. 외부 AI 환경에서 실행하면 출력이 그 서비스에 전달되므로 기관 보안 승인 범위를 확인하고 필요하면 `--mask`를 쓴다.
- 게시글 본문 오타 점검은 신규 게시글만, 상한 안에서, 한 번씩만 요청한다 (서버 부하·AI 비용 보호).

## 2. 역할 분담

| 구분 | 담당 | 내용 |
| --- | --- | --- |
| 결정적 작업 | 스크립트 (`scripts/collect.py`) | HTTP 상태, 목록 파싱, 최신 게시일, 달력 기준 3개월 판정, 링크·첨부 점검, 변경 감지, 신규·지속·해결 비교 |
| 추론 작업 | AI (`core/judgement-guide.md`) | 현행화 의심, 문구 개선, 연락처·조직 이상, 개인정보 노출 의심, 목록을 못 읽은 건의 보완 확인 |

- **AI는 스크립트가 확정한 값(상태코드, 최신 게시일, 경과 판정)을 다시 계산하거나 뒤집지 않는다.** 이상해 보이면 `담당자 확인 필요`로 표시하고 사유를 쓴다.
- 날짜 계산을 직접 하지 않는다 (`--today`와 스크립트 결과를 사용).

## 3. 결과 분류

1. 확정 오류
2. 게시 최신성 지연
3. 현행화 의심
4. 문구 개선
5. 담당자 확인 필요
6. 정상

## 4. 중요도

- 긴급: 대국민 서비스 이용 불가, 개인정보 노출 가능성(명백한 대량 노출), 주요 메뉴 전체 장애
- 높음: 404/500, 첨부파일 실패, 최신 콘텐츠 3개월 초과, 잘못된 연락처 가능성
- 보통: 문구 오류, 부분 이미지 오류, 일부 링크 이상
- 낮음: 표현 개선, 경미한 표기 불일치

## 5. 확정 오류 기준

- HTTP 404 또는 500 오류 (자동 재시도 후에도 동일)
- 페이지가 반복해서 열리지 않음
- 이미지가 깨져 표시됨
- 링크와 연결 대상이 명백히 다름
- 첨부파일 다운로드 실패 (404/410/5xx/연결 실패)
- 주요 기능이 반복적으로 작동하지 않음

401/403/405 등 접근 제한은 `담당자 확인 필요`로 둔다 (확정 오류 아님).

## 6. 오류로 보지 않는 항목

- 과거 보도자료 및 연구성과 자료 자체
- 기록 보존 목적의 과거 행사 페이지
- 종료된 공고를 아카이브로 보존한 경우
- 법령·지침 구버전 게시물
- 게시 빈도가 원래 낮은 연례 간행물

게시판별 예외는 `site-profile.json`의 `irregular`(비정기), `recency_exempt`(최신성 판정 제외), `exclude`(제외)로 지정한다.

## 7. 점검 원칙

- 오류라고 확정할 근거가 부족하면 `담당자 확인 필요`로 분류한다. 확실한 사실과 추정을 구분한다.
- 모든 지적에는 페이지 제목, URL, 발견 내용, 판단 근거를 기록한다.
- 동일 URL은 한 번만 점검한다. 쿼리스트링·앵커만 다른 동일 콘텐츠는 중복으로 본다.
- 점검하지 못한 게시판과 사유(미방문, 수집 한계, AI 판단 미실시)를 반드시 보고에 적는다. 스킵을 점검 완료로 표기하지 않는다.
- 게시 최신성 판정 기준은 `core/recency-rules.md`를 따른다.

## 8. 보고 기준

각 항목에 다음을 기록한다 (필드 정의: `core/report-fields.md`).
