# UI/UX 가이드라인 AI 화면 검토 지침

자동 규칙(`policy_check.py --pack uiux`)이 다루지 못하는 **스타일·컴포넌트 규칙**(색상, 타이포그래피, 레이아웃, 컴포넌트 사용성·접근성 등)을
AI가 **일부 페이지(기본 15개, 사용자 지정 가능)**에 대해 화면과 가이드라인 원문으로 검토한다. 입력은 `uiux-review-queue.json`이다.

## 절차

1. 대기열의 `pages`를 하나씩 본다. `screenshots`(데스크톱·모바일)가 있으면 이미지 파일을 열어 화면을 본다. `needs_browser=true`이거나 캡처가 없으면 **브라우저로 `url`을 직접 열어**(읽기 전용) 본다.
2. 페이지의 `components`(HTML에서 탐지된 컴포넌트와 가이드라인 목차의 쪽 범위)와 `style_sections`(색상·타이포·형태·레이아웃·아이콘)를 확인한다. **필요한 쪽만** 읽는다.
   ```bash
   python scripts/guidelines.py pages uiux 280-292      # 한 번에 40쪽 이하
   python scripts/guidelines.py pages uiux --find 명도 대비
   ```
   쪽 이미지(`guidelines/uiux/<버전>/source/digital_gov_guideline_pages/page_XXXX.jpg`)로 표·그림·예시(모범/피해야 할 사례)를 직접 볼 수 있다.
3. 가이드라인의 **사용성·접근성·상호작용 요건**과 화면을 대조해 항목별로 `준수 / 미준수 / 확인불가`를 판단한다.
4. 결과를 `workspace/runs/<날짜>/uiux-review.json`에 저장하고 `python scripts/uiux_review.py merge --workspace workspace`로 병합한다.

## 결과 형식 (대기열의 `result_schema`)

```json
{"model": "사용한 모델/도구", "items": [
  {"page_id": "P01", "component": "푸터", "guideline_page": 249, "guideline_quote": "원문 그대로의 구절",
   "verdict": "준수|미준수|확인불가", "observation": "화면에서 본 내용(20자 이상)", "severity": "높음|보통|낮음",
   "confidence": "high|medium|low", "evidence_ref": "스크린샷 경로 또는 선택자"}]}
```

## 원칙 (병합 단계가 자동으로 강제한다)

1. **인용 필수**: 모든 항목에 `guideline_page`와 `guideline_quote`(원문 그대로)를 적는다. 인용이 그 쪽 원문에 없으면 판정은 `확인불가`로 낮춰진다.
2. **본 것만 쓴다**: `observation`에는 화면에서 실제로 본 내용(위치·문구·색 등)을 구체적으로 쓴다. 보지 못했거나 판단 근거가 없으면 `확인불가`로 한다. 추측으로 `준수`를 주지 않는다.
3. **미준수는 근거 참조 필수**: `evidence_ref`(스크린샷 경로 또는 CSS 선택자)가 없으면 반영되지 않는다.
4. **기준값은 원문에서 확인**: `contrast`(명도 대비)·`computed_styles`는 측정값일 뿐이다. 합격 기준(예: 몇 대 몇)은 기억으로 판단하지 말고 가이드라인 원문의 해당 쪽(색상 74~101쪽, 타이포그래피 102~125쪽 등)을 읽고 인용한다.
5. **범위 한정**: 페이지에 실제로 있는 컴포넌트만 검토한다. 없는 컴포넌트에 대해 `준수`를 만들지 않는다. 로그인 필요 화면·관리자 화면은 보지 않는다.
6. **브랜드 재량 존중**: 가이드라인이 "권장"·"고려"로 표현한 항목은 `미준수`가 아니라 `확인불가` 또는 낮은 `severity`로 한다. 단호한 표현("~해야 한다", "~하지 않는다")만 미준수의 근거로 쓴다.
7. **심각도**: 접근성(대체 텍스트·대비·초점)·신뢰 요소(공식 배너·식별자·개인정보 처리방침)는 `높음`, 컴포넌트 사용성 일탈은 `보통`, 시각적 일관성은 `낮음`.
8. 점검 결과는 **참고용**이며 사람의 최종 확인 전이라는 점을 보고서에 유지한다. 사이트를 수정하는 행동(입력, 제출, 로그인)을 하지 않는다.

## 보고

미준수 항목은 가이드라인 쪽 이미지 경로와 화면 근거를 함께 담당자에게 전달한다. 병합 결과(`uiux-review.md`)의 "인용 검증 실패"·"형식 오류로 제외" 항목은 다시 검토한다.
