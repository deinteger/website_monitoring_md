## 3. 제출용 저장소 만들기 (GitLab)

현재 GitHub 저장소의 **git 이력(이전 커밋·main)에는 실제 기관 점검 데이터가 남아 있다**(최신 파일에서는 삭제함). 이력째 GitLab에 올리면 안 되므로, 배포 빌더가 만든 깨끗한 폴더(`dist/website-monitoring-kit-v버전/`)의 내용으로 새 저장소를 만든다(zip 파일째가 아니라 압축을 푼 파일들을 올린다).

```bash
python scripts/make_release.py                      # dist/website-monitoring-kit-vX.Y.Z/ (workspace·실제 점검 데이터 제외, 가이드라인은 규칙·목차만)
cd dist/website-monitoring-kit-v1.0.0
git init && git add . && git commit -m "2026 공공 AI 대전환 챌린지 세션1 제출"
git remote add origin <GitLab 프로젝트 주소> && git push -u origin HEAD:main
```

- 빌더는 허용 목록 방식으로 복사하고, 실제 기관 도메인이 문서에 섞여 있으면 중단한다.
- 가이드라인 원문까지 넣으려면 `--with-guideline-source`(원문 md 1MB), 쪽 이미지까지는 `--with-images`(약 34MB). **원문 이용 조건(공공누리 유형 등)을 확인한 뒤에만** 사용한다. 기본값은 원문 제외다.
- GitLab 프로젝트: 공개 범위 **비공개**, 일반 → 주제(Topics)에서 `2026 공공 AI 대전환 챌린지 세션1` 선택.
- **마지막 커밋 전에 아래 4항 점검을 끝낸다.** 마감 후 변경은 불가하다.

## 4. 제출 전 점검 (이 순서로)

1. **제출 폴더(dist/…)에서** `python scripts/demo.py` — 외부 접속·API 키 없이 끝까지 구동되는지(심사위원 구동 환경 재현). 저장소 원본이 아니라 제출용 패키지로 확인해야 한다
2. `python -m unittest discover -s tests` — 자동 테스트 통과
3. 제출 폴더에 실제 기관 데이터·키·개인정보가 없는지 (`workspace/`, `*.csv` 결과, `.env`)
4. README에 **접속 주소(없으면 "로컬 실행")·주요 기능·실행·작동 방법**이 있는지, 구동안내서와 README의 실행 순서가 같은지

## 6. 확인 필요 (제가 확인하지 못한 것)

| 항목 | 왜 중요한가 |
| --- | --- |
| 마감 시각 | 문서에 시각이 없음 |
| **소속 기관의 사용권 부여 동의** | 신청서에 "참가팀과 소속 기관은 행정안전부에 무상 사용권(복제·수정·배포·2차적 저작물·범정부 공동활용) 부여" 동의가 있어 기관 차원 승인이 필요할 수 있음 |
| 가이드라인 원문 재배포 조건 | 저장소 원본에는 UI/UX 가이드라인 원문·이미지가 있음(제출용 폴더에서는 제외). 구동안내서 '알려진 제약'에 재배포 제한 구성요소를 명시해야 함 → 이용 조건(공공누리 유형 등) 확인 |
| 2종 이상 모델 구동 입증 | 안내서가 권장(`eval_judge.py`로 모델별 정확도 표 작성 가능). **API 키가 있어야 하며 이 환경에서는 실행하지 못함** |
| 공공 GitLab 접속 환경 | 업무망/인터넷 접속 가능 여부 |
| **심사 환경의 Python 설치 여부** | 키트는 Python 3.8+만 필요하지만 실행기를 포함하지 않는다. 심사 환경에 없을 수 있으므로 구동안내서 '실행 환경'에 필수 소프트웨어로 명시하고, 가능하면 임베디드 Python을 `python/`에 포함하거나 질의(NIA)로 확인 |
| 공통기반 지원 모델의 API 형식 | OpenAI 호환이면 환경변수만으로 연결되나, 형식은 확인 필요 |
