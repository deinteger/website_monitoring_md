# 구동 안내서 (양식 2-1 초안, 5쪽 이내) — 홈페이지 정책 준수 자동 점검 키트

> 양식 2-1의 항목 순서를 따른 초안이다. 팀명·기관명·연락처는 비워 두었다. PDF로 변환해 `[구동안내서]_기관명_팀명.pdf`로 제출한다.

## 1. 실행 환경

- OS: Windows / Linux / macOS (Python 3.8 이상이 있으면 동작)
- 필요 소프트웨어: **Python 3.8 이상만 필요하다. 외부 패키지 설치가 필요 없다**(표준 라이브러리만 사용). 브라우저·인터넷 접속 불필요(데모 기준)
- 권장 사양: 일반 업무용 PC. 실제 사이트 점검 시 점검 대상에 접근 가능한 PC

## 2. 설치·실행 절차 (처음부터 순서대로)

1. 저장소를 내려받아 폴더로 이동한다.
2. 데모를 실행한다 (모의 기관 사이트와 모의 LLM이 로컬에 자동으로 뜬다).
   ```
   python scripts/demo.py
   ```
3. 화면에 출력되는 **결과 요약**과 **결과 파일 목록**을 확인한다. 결과는 `workspace/demo/runs/<날짜>/`에 생성된다.
4. (선택) 모의 사이트를 브라우저로 보려면 `python scripts/demo.py --serve` 후 출력된 주소의 `/home`을 연다.
5. (선택) 자동 테스트: `python -m unittest discover -s tests`

## 3. LLM 연결 설정

- 데모의 AI 판단은 **모의 LLM(규칙 기반, 실제 AI 모델이 아님)**이 응답한다. 외부 접속·API 키 없이 구동을 확인하기 위한 장치다.
- 실제 모델 연결(OpenAI 호환 `/chat/completions` 또는 Anthropic): 환경변수 4개만 바꾸면 된다. **키는 파일에 저장하지 않고 환경변수로만 입력한다.**
  ```
  LLM_PROVIDER=openai          # 또는 anthropic
  LLM_BASE_URL=<엔드포인트 주소>
  LLM_API_KEY=<개인 키>
  LLM_MODEL=<모델명>
  ```
  그리고 `workspace/settings.json`의 `"llm": {"allowed": true}` 로 외부 AI 전송을 명시적으로 허용한다(기본은 거부).
- **모델 교체·이식성**: 모델 이름과 엔드포인트만 바꾸면 되며 코드 수정은 없다. 모델별 판단 정확도는 합성 정답 14건으로 비교한다: `python scripts/eval_judge.py`.
- 공통기반 지원 모델(Gemma, GPT-OSS, EXAONE, HyperCLOVA X, Solar)은 OpenAI 호환 엔드포인트로 제공되는 경우 같은 방식으로 연결할 수 있다(엔드포인트 형식은 **확인 필요**).
- 안전장치: 외부 전송 전 개인정보(주민번호·전화·이메일) 마스킹, AI가 낸 지적은 **원문 인용이 입력에 실제 있는 경우만 채택**(환각 차단).

## 4. 모의데이터 안내

- 별도 파일 없이 `scripts/demo.py`가 가공한 **모의 기관 사이트**(게시판 3개, 게시글 8건, 조직도·연락처, 의도적 결함 포함)를 생성한다. 개인정보·실제 기관 정보는 없다.
- 실제 사이트 점검 시에는 `config.example/`의 프로필·설정 예시를 `workspace/`로 복사해 쓴다.

## 5. 기능 사용 순서 (핵심 흐름 3개)

**흐름 1 — 전체 점검**: `python scripts/demo.py` 또는 `python scripts/run_checks.py --workspace workspace --checks all`
점검 범위는 선택할 수 있다: 게시판 / 게시글 오타 / 정책정보 확인주간 / 범정부 UI·UX 가이드라인 / 검색 포털(구글·네이버·다음). `--list`로 선택지, `--dry-run`으로 요청량 확인.

**흐름 2 — 결과 확인과 사람 응답**: `inspection-summary.md`(요약), `policy-policy-week.csv`(정책정보 확인 체크리스트: 자동 판정·증거·사람 응답 구분), `policy-uiux.md`(가이드라인 쪽 근거 포함). 홈페이지로 확인할 수 없는 문항은 **사람이 응답**한다: `python scripts/policy_check.py answer PW-03 --yes --note "..."`.

**흐름 3 — 질의**: 사이트에 들어가지 않고 묻는다.
```
python scripts/recent_changes.py --workspace workspace/demo --days 7 --include-today   # 최근 현행화된 게시물
python scripts/lookup.py --workspace workspace/demo contact 연락처                        # 공개된 담당부서·연락처
```

## 6. 알려진 제약 사항

- **모의 LLM은 실제 AI가 아니다.** 실제 AI 판단은 4항의 환경변수로 모델을 연결해야 한다.
- 실제 기관 사이트 점검은 **요청 트래픽이 발생**한다. 기본값은 보수적(동시 2건, 1초 간격, 차단 의심 시 자동 중단)이며, 실행 전 정보보안 담당과 협의해야 한다(`docs/보안통보_요청서_양식.md`).
- 자바스크립트로 그려지는 페이지는 기본 구성으로 읽지 못한다. 선택 모듈 Playwright(별도 설치 필요, Apache-2.0)나 AI 에이전트 브라우저로 보완한다.
- 정책정보 확인 체크리스트의 **네/아니오 응답은 사람이 한다.** 자동 결과는 근거 수집과 참고 판정이며, 근사 측정(용량·로딩, 접근성 일부)의 한계를 결과에 표시한다.
- 범정부 UI/UX 가이드라인의 자동 점검은 HTML로 확인되는 요건(공식 배너·식별자·헤더·푸터·건너뛰기 링크)이며 규칙마다 원문 쪽·인용문을 가진다. 나머지 스타일·컴포넌트 규칙은 AI 화면 검토 또는 사람 확인 대상이다.
- **재배포 제한 가능 구성요소**: 가이드라인 원문(디지털 정부서비스 UI/UX 가이드라인 2025.08, 정책정보 확인 점검 체크리스트)은 출처 문서이며 이용 조건은 **확인 필요**. 제출 저장소에는 규칙(근거 쪽·짧은 인용)만 포함하고 원문 전체는 제외했다.
- 참고한 자료·출처: 디지털 정부서비스 UI/UX 가이드라인(2025.08), 정책정보(웹사이트 관리) 확인 점검 체크리스트, 전자정부 웹사이트 품질관리 지침(체크리스트 인용).

## 7. 개발 경위 요약 (1쪽 이내)

**문제 인식**: 정책정보 확인주간과 홈페이지 품질관리 점검은 담당자가 수십~수백 개 게시판을 일일이 열어 보며 최신성, 링크, 오타, 가이드라인 준수 여부를 확인한다. 시스템마다 사이트 구조가 달라 단순 스크립트만으로는 판단(현행화 의심, 가이드라인 해석)이 빠지고, AI만으로는 날짜 계산·링크 확인 같은 사실 확인에서 오류와 비용이 크다.

**접근 방식**: (1) **사실은 스크립트가, 추론은 AI가** — 상태코드·3개월 판정·링크·변경 감지는 스크립트가 확정하고, 현행화 의심·오타 같은 판단만 AI에 맡긴다. (2) **AI 판단의 환각 차단** — AI가 낸 지적은 입력 원문에 실제 있는 인용문일 때만 채택한다. (3) **규칙은 데이터로** — 매년 개정되는 가이드라인은 `guidelines/`의 규칙 데이터(쪽·인용문 근거)로 관리하고, 개정판을 올리면 `validate`가 원문 인용을 검증한다. (4) **사람이 응답할 문항은 사람이** — 계획 수립 여부 같은 문항은 자동으로 채우지 않는다. (5) **모델·환경 비종속** — 표준 라이브러리 전용, 모델은 환경변수로 교체, Claude Code·pi·Codex·Cline 등 에이전트에서 같은 지침으로 동작.

**검증**: 가짜 사이트 기반 자동 테스트와, 실제 공공기관 공개 홈페이지 1곳에 대한 읽기 전용 확인으로 결함(스크립트 이동 껍데기 페이지, 한글 담당자 정보가 만드는 헤더 오류 등)을 찾아 수정했다.
