# 홈페이지 점검 도구 실행 협조 요청서 (양식)

> 정보보안 담당·시스템 운영 부서에 보내는 사전 통보 및 허용 요청용 양식이다. `[ ]`를 채워 사용한다.
> `python scripts/collect.py --workspace workspace --mode full --dry-run` 결과(요청 수·예상 시간)를 아래 3항에 옮겨 적는다.

## 1. 요청 개요

- 요청 부서/담당자: [부서] [성명] ([연락처])
- 대상 시스템: [시스템명] ([도메인])
- 목적: 홈페이지 링크 오류, 게시물 최신성(3개월), 접속 상태의 정기 점검 (읽기 전용 점검)
- 요청 사항: 아래 점검 트래픽을 **공격으로 오인하지 않도록 사전 인지** 및 필요 시 **허용 목록(웹방화벽·IPS·DDoS 장비) 등록**, 호출 제한(rate limit) 예외 적용

## 2. 점검 방식

- 도구: 홈페이지 점검 키트 (파이썬 표준 라이브러리 기반, 외부 패키지 없음)
- 요청 방법: **GET, HEAD 만 사용**. 로그인·입력·업로드·수정·삭제 없음. 대상 도메인 밖으로 접속하지 않음
- User-Agent: `[settings.json 의 user_agent (+contact)]` — 이 값으로 점검 트래픽을 식별할 수 있음
- 동시 요청 수: [max_concurrency]  / 요청 간 최소 간격: [min_interval_sec]초 (전체 합산 기준)
- 안전장치: 403/429 응답이 **연속 [abort_after_blocked]회** 발생하면 즉시 중단하고 재시도·우회하지 않음. 응답 지연·오류 시 자동 재시도는 [retries]회로 제한
- 점검 모드: 일상 점검(증분) — 점검 주기가 도래한 게시판만 방문 / 전체 점검 — 월 1회

## 5. 협조 요청

1. 위 IP·User-Agent 트래픽의 허용(또는 차단 제외) 등록 — 가능 여부 및 적용 시점 회신
2. 허용이 어려운 경우 대안 협의 (요청 간격 확대, 시간대 조정, 내부망 실행)
3. 점검 중 장애·경보가 발생하면 즉시 중단할 수 있도록 연락처 공유: [ ]

## 6. 외부 AI 서비스 사용 (해당 시)

- 점검 결과 일부(게시판 제목·본문 발췌, 개인정보 마스킹 후)를 외부 AI 서비스로 전송하여 현행화·문구 판단을 수행하는 경우, 기관 보안 정책상 허용 여부 확인이 필요함 → [허용 / 불가 / 협의 중]
- 불허 시: AI 판단 없이 스크립트 점검만 수행(`--judge no`)하고 AI 항목은 담당자가 직접 확인
