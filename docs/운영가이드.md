# 운영 가이드

## 1. 준비물

- Python 3.8 이상 (외부 패키지 설치 불필요 — 표준 라이브러리만 사용)
- 점검 대상 접근이 가능한 PC/서버 (내부망 사이트는 내부망 PC에서 실행)
- (선택) AI: Claude Code, pi(Orca 포함), Codex, Antigravity 중 하나 **또는** OpenAI 호환/Anthropic API 키

## 2. 처음 시작 (담당자)

1. 이 폴더를 받는다 (배포 zip 압축 해제 또는 저장소 복제).
2. `workspace/settings.json` 작성: `config.example/settings.example.json`을 복사하고 `contact`(담당 부서·연락처)를 채운다.
3. 정보보안·운영 부서에 통보 (`docs/보안통보_요청서_양식.md`). 요청량은 `--dry-run`으로 산출한다.
4. 온보딩: `core/onboarding.md` (초안 생성 → 검수 → `site-profile.json`). 에이전트에게 맡길 수 있다 (`docs/pi-orca.md`).
5. 시험 점검: `python scripts/collect.py --workspace workspace --mode full --limit 20`
6. 전체 점검 → 이후 일상 점검(증분).

## 3. 점검 모드

| 모드 | 방문 대상 | AI 판단 대상 | 용도 |
| --- | --- | --- | --- |
| `incremental` (기본) | 점검 주기가 도래한 게시판, 신규, 직전 오류, 오늘 새로 지연이 되는 게시판 | 신규·변경·이상 건만 | 매일·매주 |
| `full` | 전체 | 전체 | 최초, 월 1회, 규칙 변경 후 |

- 방문하지 않은 게시판도 **날짜 경과 판정은 매번 재계산**한다 (`recency-status.csv`의 `캐시(미방문)`).
- 링크·첨부 점검은 게시판별로 `link_check_interval_days`(기본 7일)마다, 변경 시, 전체 점검 시 수행한다. 같은 URL은 한 번만 요청한다.
- `--sample-rate 0.1`: 변경 없는 방문 게시판의 10%를 AI 판단에 추가 포함 (영구 스킵 방지).
- `--resume`: 같은 날짜 실행이 중단된 지점부터 이어서 실행. `--only a,b`: 특정 게시판만.
- 마지막 전체 점검 후 `full_every_days`(기본 30일)가 지나면 요약에 경고가 표시된다.

## 4. 요청 정책 (서버 보호)

기본값은 보수적이다: 동시 2, 전체 요청 간격 1초, 오류 시 재시도 2회, 403/429 연속 5회면 중단.
1,000개 게시판 목록 방문은 약 17분 이내다(링크 점검 제외, `--dry-run`의 예상 시간 참고).
정책 완화는 **보안·운영 부서 협의 후** `settings.json`에서만 한다. 차단되면 우회하지 말고 허용 목록 등록을 요청한다.

## 5. 스케줄링

일상 점검(증분)은 스케줄러에 등록한다. AI 판단 없이 수집·요약만 자동화하고, 판단은 필요할 때 에이전트로 하는 구성이 가장 단순하다.

```bash
# Linux/macOS cron (평일 07:10)
10 7 * * 1-5 cd /경로/website_monitoring_md && python3 scripts/run_all.py --workspace workspace --mode incremental --judge no
```

```bat
:: Windows 작업 스케줄러 (평일 07:10)
schtasks /Create /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 07:10 /TN "홈페이지점검" /TR "python C:\경로\website_monitoring_md\scripts\run_all.py --workspace C:\경로\website_monitoring_md\workspace --mode incremental --judge no"
```

- 월 1회 전체 점검은 `--mode full`로 별도 등록한다.
- 종료코드 2(차단 의심 중단)는 스케줄러 알림으로 확인하도록 설정한다.
- API로 AI 판단까지 자동화하려면 6절을 설정하고 `--judge auto`를 쓴다 (환경변수가 스케줄러 실행 계정에 설정되어 있어야 한다).

## 6. API로 AI 판단 (선택)

에이전트(Claude Code, pi 등)를 쓰지 않고 스크립트가 직접 LLM을 호출하는 방식이다. **외부 AI 서비스로 점검 내용이 전송되므로 기관 보안 승인 후** 사용한다.

1. `workspace/settings.json`에 `"llm": {"allowed": true, "provider": "openai", "base_url": "...", "model": "..."}`.
2. API 키는 파일에 저장하지 않고 환경변수로 준다.

   ```bash
   export LLM_API_KEY=발급받은키          # Windows: set LLM_API_KEY=...
   python scripts/judge.py --workspace workspace --dry-run       # 건수·입력 크기만 확인
   python scripts/judge.py --workspace workspace                 # 판단 실행 (상한 100건, 배치 5건)
   ```

3. 공급자: `openai`(OpenAI 호환 `/chat/completions`, timelygpt 등) 또는 `anthropic`(`/v1/messages`).
   **timelygpt는 base_url·사용 가능 모델명·호출 한도가 제공 사양에 따라 다르므로 발급 안내 문서로 확인 필요**하다. 호환되지 않으면 pi/Claude Code 등 에이전트 경로를 쓴다.
4. 안전장치: 승인 전 실행 거부, 개인정보 마스킹 후 전송, 건수 상한(`--max-items`), **원문 인용 검증**(원문에 없는 인용은 '담당자 확인 필요'로 하향), 호출 실패 항목은 사람 확인으로 표기.
5. 모델·규칙 변경 시 정확도 비교: `python scripts/eval_judge.py --min-accuracy 0.8` (합성 정답 14건).

## 7. 월간 보고

`python scripts/monthly_report.py --workspace workspace --month YYYY-MM` (월 생략 시 지난달)

- 신규 등록 콘텐츠 건수, 게시 최신성 정상률, 월 중 갱신 게시판, 지연→정상 전환(현행화 개선), 지적 신규·지속·해결을 **전월 대비**로 표시한다.
- 첫 달은 비교 기준이 없어 `비교 기준 없음`으로 나온다. 다음 달부터 증감이 계산된다.
- 신규 콘텐츠는 수집한 목록 범위 내 집계다. 글이 많은 게시판은 `pages`를 늘려야 월 전체가 집계된다 (`부분(하한값)` 표시 참고).
- `monthly-report.md`의 `AI_COMMENT` 자리는 에이전트가 채운다. 한글(hwpx)·엑셀 보고서 변환은 포함되어 있지 않다 (`monthly-boards.csv`는 Excel에서 바로 열린다).

| 증상 | 조치 |
| --- | --- |
| `게시일 확인 불가` | `--probe <id>`로 확인 → `region`/`row_tag` 지정, 날짜가 특이하면 `date_regex` |
| 최신 게시일이 화면과 다름 | 날짜 열이 여러 개(행사일 등) → `date_regex` 또는 `date_source` |

| 목록이 비어 보임 (`js_suspected`) | 스크립트는 기본적으로 JS를 실행하지 않는다 → 아래 9절의 3가지 중 선택 |

## 9. 자바스크립트로 그려지는 목록 처리 (선택)

"JS 게시판"이란 페이지 소스(HTML)에는 글 목록이 없고, 브라우저가 자바스크립트를 실행해 목록을 그려 넣는 게시판이다. 사람 눈에는 정상으로 보이지만 스크립트는 빈 페이지로 읽는다.
확인법: 브라우저에서 "페이지 소스 보기"를 열어 글 제목이 보이면 해당 없음. `--probe`에서 `js_suspected`가 나오면 해당.

| 선택 | 설정 | 비용 | 리스크 | 난이도 |
|---|---|---|---|---|
| A. 에이전트 브라우저로 보완 (기본) | 아무 설정 없음. `js_suspected` 건을 에이전트가 열어 확인 | 해당 건만 토큰 소모 | 브라우저 없는 환경이면 '담당자 확인 필요'로 남음 | 낮음 |
| B. 서버 렌더링 주소 사용 | 같은 목록을 HTML로 주는 주소를 찾아 프로필 `url`에 입력 | 없음 | 사이트마다 가능 여부 다름 | 낮음~중간 |
| C. Playwright 자동 렌더링 | 게시판별 `"render": "playwright"` 또는 `settings.json`에 `"js_fallback": "playwright"`(목록을 못 읽은 게시판만 렌더링) | 요청·시간 증가 | 설치 필요(기관 PC 제한 가능), 하위 요청 증가로 차단 가능성 | 중간 |

- C 설치(원하는 담당자만): `pip install playwright` 후 `playwright install chromium`. 설치가 어려우면 `settings.json`의 `render.executable_path`에 PC의 Chrome/Chromium 실행 파일 경로를 지정할 수 있다 (동작은 Chromium 계열 기준이며 설치된 버전과의 호환은 **확인 필요**).
- 브라우저는 허용 도메인 밖 요청을 차단하고(설정 시) 이미지·글꼴·미디어를 받지 않는다. 페이지 이동은 일반 요청과 같은 간격을 지키지만 스크립트·API 하위 요청은 별도로 발생하므로 **보안 통보 시 렌더링 사용 여부를 함께 알린다.**
- Playwright가 없거나 실행에 실패해도 점검은 중단되지 않고 해당 게시판이 `render_unavailable`로 표시되어 A 경로(확인 필요)로 남는다.
- 게시판별 지정 예: `{"id":"x","name":"...","url":"...","render":"playwright","render_wait":"table.board tr"}`

## 11. 검색엔진 인덱스 점검 (구글·네이버·다음)

`site:도메인` 검색 결과에 남은 **깨진 링크(404), 소프트 404, 메인으로 튕기는 링크, 깨진 이미지, 제목 불일치**를 찾는다.
점검(접속·제목 비교·이미지 확인)은 스크립트가 하고, **결과 URL 수집은 엔진 특성상 아래 방법 중 선택**한다.

| 수집 방법 | 내용 | 비용 | 리스크 | 난이도 |
|---|---|---|---|---|
| A. 에이전트 브라우저 (기본) | 에이전트가 3개 엔진에서 `site:`를 검색해 URL·제목 목록 저장 | 토큰 소모 | 캡차·차단 시 중단됨, `site:` 결과 수 제한 | 낮음 |
| B. 사람이 복사 | 담당자가 결과 URL을 메모장에 붙여넣기 | 없음 | 수작업, 누락 | 최저 |
| C. 공식 검색 API | 구글 Custom Search, 네이버·카카오(다음) 검색 API 키로 수집 | 쿼터·키 관리 | 결과 수·`site:` 지원 범위·약관 **확인 필요**, 현재 키트에는 미구현 | 중간 |

- 스크립트로 검색 페이지를 직접 긁는 방식은 약관 위반 소지와 봇 차단 때문에 넣지 않았다.
- 명령: `python scripts/check_index_links.py --workspace workspace --check-images --input google=파일 --input naver=파일 --input daum=파일` (`--dry-run`으로 요청 수 확인). 파일은 한 줄에 `URL<탭>검색결과제목`.
- 한계: CSS 깨짐 같은 **화면 렌더링 오류는 브라우저로만** 확인된다. 스크립트가 보는 것은 상태코드, '페이지 없음' 문구, 빈 페이지, 제목, 같은 도메인 이미지의 404다.
- 결과는 `search-index-links.csv`로 별도 관리한다 (게시판 점검의 신규·지속·해결 이력에는 합치지 않는다).
- `제목불일치`·`빈페이지의심`·`리다이렉트오류`는 오탐 가능성이 있어 브라우저로 확인 후 확정한다.

## 12. 질의: 어제·그제 현행화된 게시물, 현황, 담당자 연락처

사이트에 일일이 들어가지 않고 에이전트나 명령으로 묻는다. 에이전트에게는 말로 물으면 `core/skill-body.md` 7절의 명령으로 연결된다.

| 질문 | 명령 | 네트워크 |
|---|---|---|
| 어제 그제 현행화된 게시물 | `python scripts/recent_changes.py --days 2` (`--refresh`를 붙이면 점검 후 조회) | 없음 |
| 최근 일주일 | `python scripts/recent_changes.py --days 7 --include-today` | 없음 |
| 게시판 현황 / 전체 현황 | `python scripts/lookup.py status 보도자료` / `overview` | 없음 |
| 담당자·연락처 | `python scripts/lookup.py contact 보도자료` (최신 글 기준은 `--latest-post`, 임의 페이지는 `--url`) | 해당 페이지 1회 |

- **기간**: "어제·그제"는 오늘을 뺀 2일(`--days 2`). 기준은 기본이 목록의 **게시일**이고 `--by seen`은 이 키트가 **처음 확인한 날짜**다 (최초 수집분은 확인일을 알 수 없어 제외).
- **데이터 신선도**: 조회는 마지막 점검 시점까지의 데이터다. 결과의 `주의`에 "마지막 점검일 이후 미반영", "증분 점검 주기로 방문하지 않은 게시판"이 표시된다.
- **담당자 연락처**: 해당 페이지에 **공개된 표기만** 찾고 추정하지 않는다. 본문 표기와 푸터(기관 공통) 표기를 구분해 근거 원문과 함께 보여 준다. 목록 페이지에는 대표번호만 있는 경우가 많아 특정 글은 `--latest-post`/`--url`이 필요하다. 못 찾으면 못 찾았다고 답한다.
- **개인정보**: 연락처는 저장하지 않는다. 외부 AI 환경에서 실행하면 출력이 그 서비스에 전달되므로 기관 보안 범위를 확인하고, 필요하면 `--mask`를 쓴다.

### 환경별 주기 실행과 질의

| 환경 | 주기 실행 | "어제 그제 뭐 올라왔어?" |
|---|---|---|
| 로컬 PC/서버 + 스케줄러 | 가능. `python scripts/make_schedule.py --os windows --time 07:10`이 등록 명령을 출력 | 에이전트가 명령 실행, 또는 매 실행 후 갱신되는 `reports/recent/latest.md` 열람 |
| Claude Code, pi/Orca, Codex, Antigravity, Cline | 에이전트 자체의 반복 실행 기능 유무는 도구·버전별로 **확인 필요**. 확실한 방법은 스케줄러 등록 | 가능 (스킬·AGENTS.md로 명령 연결) |
| Claude 채팅 | 자동 실행 불가(수동 요청). 점검은 사이트 접속 허용이 필요 | `state.zip`을 올리면 가능. 조회·현황은 **접속 없이** 동작, 담당자 연락처는 접속 필요 |
| GPT·제미나이 등 채팅 | 자동 실행 불가 | `reports/recent/latest.md`(또는 `.json`)를 올리고 질문하면 파일 내용 기준으로 답변. 파이썬 실행 지원 여부는 **확인 필요** |

주의: 채팅에서 파일만 올려 답하는 방식은 AI가 파일 내용을 읽는 것일 뿐 점검이 아니다. `latest` 파일의 날짜 범위(최근 14일)와 마지막 점검일을 함께 확인한다.

## 13. 게시글 본문 오타 점검 (선택)

기본은 꺼져 있다. 켜면 신규 게시글 상세 페이지를 추가로 요청하고 AI가 본문을 판단한다.

- 켜기: `settings.json`의 `"typo_check": {"enabled": true}` 또는 실행 때 `--typo-check`
- 부하·비용 상한: 게시판당 최신 `max_posts_per_board`(기본 3)건, 실행당 `max_posts_per_run`(기본 30)건. **한 번 점검한 글은 다시 요청하지 않는다.** 상한을 넘은 글은 다음 실행에서 이어서 점검한다. 게시판별로 `"typo_check": false`로 제외할 수 있다.
- 본문 영역: 프로필의 `body_region`을 지정하면 정확하다 (미지정 시 휴리스틱). `python scripts/collect.py --probe <id> --probe-post`로 본문 추출 결과를 미리 본다. 본문을 못 찾은 글은 요약의 점검 한계에 사유와 함께 표시된다.
- 판단: `python scripts/judge.py --task typo` 또는 에이전트가 `core/typo-guide.md` 기준으로 판단. 원문에 없는 인용과 수정안이 같은 항목은 자동으로 버린다. 고유명사·전문용어는 오류로 보고하지 않는다.
- 한계: 맞춤법 판단은 AI 추론이라 오탐·미탐이 있다. 결과는 "수정 검토 대상"으로 담당 부서에 전달하고 확정은 사람이 한다. 한글(HWP) 변환 흔적, 표·목록 줄바꿈은 오탐 원인이 될 수 있다.
- 보안: 본문은 개인정보 마스킹 후 AI에 전달되며 이름·주소는 마스킹되지 않는다. 외부 AI 전송은 기관 보안 승인 후에만 한다. 보안 통보 시 상세 페이지 요청이 늘어남을 함께 알린다 (`--dry-run`의 `typo_post_requests_upper_bound`).

## 14. 점검 범위 선택 (run_checks)

`python scripts/run_checks.py --list`로 선택지를 보고 `--checks`로 조합한다. 범위를 말하지 않으면 에이전트가 먼저 물어본다.

| 선택 | 내용 | 사이트 요청 | AI |
|---|---|---|---|
| all | 게시판 + 정책정보 + UI/UX + 포털 (오타는 설정에서 켠 경우) | 위 항목의 합 | 선택 |
| board | 접속·링크 오류, 3개월 최신성, 변경 감지 | 목록 수 + 링크 | 선택 |
| typo | 신규 게시글 본문 오타 | 신규 글 상세(상한) | 필요 |
| policy | 정책정보 확인주간 체크리스트 | 대표 페이지 최대 8개 + 자원 크기 | 불필요 |
| uiux | 범정부 UI/UX 가이드라인 | 대표 페이지 최대 8개 | 불필요 |
| portal | 구글·네이버·다음 `site:` 점검 | 검색 URL 수집(브라우저) + 결과 URL | 불필요 |

- `--dry-run`: 요청량 확인(보안 통보용). `--interactive`: 번호로 고르기. 실행 후 `runs/<날짜>/checks-summary.md`에 점검별 상태와 결과 파일 위치가 정리된다.
- 종료코드 4는 **검색 포털 점검에 URL 수집이 필요**하다는 뜻이다(오류 아님).

## 15. 정책정보 확인주간 점검 (guidelines/policy-week)

체크리스트 22개 항목과 붙임1(성별영향평가)을 규칙으로 옮겼다. 홈페이지로 확인할 수 없는 문항이 많아 **판정 방식을 3가지로 나눈다.**

| 방식 | 의미 | 예 |
|---|---|---|
| 자동(auto) | 스크립트가 충족/미충족을 판정 | 웹페이지 용량 3MB·로딩 3초(근사), 외부 링크 단절(옵트인) |
| 증거 수집(assist) | 증거만 모으고 **충족이라고 단정하지 않음** | 지도 사용 페이지 목록(독도·동해 표기는 사람이 확인), 접근성·호환성 참고 지표, 조직도 갱신일 |
| 사람 확인(attest) | 사람이 네/아니오 응답 | 관리계획 수립 여부, 사용자 평가 실시 여부, 불법정보 처리 |

- 실행: `python scripts/run_checks.py --checks policy` 또는 `python scripts/policy_check.py --pack policy-week`
- 결과: `runs/<날짜>/policy-policy-week.csv`(체크리스트 형식: 구분·항목·판정 방식·자동 판정·제안 응답·사람 응답·근거), `.md`, `.json`
- **사람 응답 기록**: `python scripts/policy_check.py answer PW-03 --yes --note "관리계획 수립(2026.3.)"` / 현황 `policy_check.py status`. 응답은 규칙팩 버전과 함께 저장되며, 개정 후에는 "이전 버전 응답: 재확인 필요"로 표시된다. 자동 결과는 **제안**일 뿐 응답을 대신하지 않는다.
- 프로필 `policy` 항목: `agency_name`, `pages`(org_chart, contact 등 증거 수집 대상), `sample_pages`, `home_url`
- **한계(근사 측정)**: 용량은 HTML과 같은 도메인 자원의 Content-Length 합, 로딩은 HTML 응답 시간으로 잰 근사치다. 접근성은 33개 검사항목 중 일부(대체텍스트·제목·언어·건너뛰기 링크)만 참고 지표로 보며 전용 검사도구와 장애유형별 사용자 평가를 대신하지 않는다. W3C Validator는 외부 서비스라 호출하지 않는다.
- **외부 링크 단절(PW-06)**은 외부 사이트에 HEAD 요청이 나가므로 기본 꺼짐이다. `settings.json`의 `policy.check_external_links=true`로 켜며(상한 `max_external_links`) 보안 통보에 포함한다.
- 불법 광고 점검(PW-09)은 `--checks portal`의 결과를 참조한다 (붙임2 키워드 137개).

## 16. 범정부 UI/UX 가이드라인 점검 (guidelines/uiux)

「디지털 정부서비스 UI/UX 가이드라인」(2025.08, 1,181쪽)의 **원문 쪽과 인용문에 근거한 규칙 24개**다 (`guidelines.py validate`가 인용을 원문에서 검증). 범위는 HTML로 확인 가능한 요건으로 한정했다.

- **자동 13개**: 공식 배너 문구·최상단 위치·건너뛰기 링크 선행, 식별자 안내 문구, 푸터 `<footer>`·'개인정보 처리방침'·링크 단절, 헤더·푸터 로고 대체텍스트, 건너뛰기 링크 존재·개수·목적지
- **증거 수집 4개**, **사람 확인 6개**(로고 위치, 유틸리티 링크, 국기 사용, 자체 검증 체크리스트 등)
- **범위 밖(미포함)**: 색상·타이포그래피·간격 등 스타일 규칙과 나머지 컴포넌트(약 100개)는 계산된 스타일·상호작용 확인이 필요하다. 자체 검증 체크리스트(UX-X1)로 사람이 점검한다.
- 결과는 규칙마다 원문 쪽(`p.224` 등)이 표시된다. 판정은 소스 기준 근사이므로(예: 헤더·푸터 영역은 `header`/`footer` 요소 또는 class·id 흔적) 미충족은 **화면으로 확인 후 확정**한다. 쿠키 배너·모달이 있으면 "첫 요소" 규칙은 예외다(p.261).
- 규칙팩이 `reviewed=false`(검수 전)이면 결과에 주의 문구가 붙는다. 담당자가 규칙을 검토한 뒤 `reviewed=true`로 바꾼다.

## 17. 가이드라인 개정 반영 (매년)

개정판을 git에 올리면 갱신된다. 절차 전체는 `core/guideline-update.md`.

```bash
python scripts/guidelines.py list                                  # 현재 버전·규칙 수
python scripts/guidelines.py new uiux 2026.08 --from 2025.08       # 새 버전 초안(전부 draft)
python scripts/guidelines.py pages uiux 220-232                    # 원문 쪽 읽기 (--find 키워드)
python scripts/guidelines.py validate --pack uiux                  # 스키마·원문 인용 검증
python scripts/guidelines.py diff uiux 2025.08 2026.08             # 개정 비교
python scripts/guidelines.py use uiux 2026.08                      # 검수 후 현재 버전 전환
```

## 18. 데이터와 배포

- `workspace/`에는 프로필·설정·캐시·이력·결과가 있다. **커밋·배포하지 않는다** (`.gitignore` 처리됨). 백업은 담당자가 별도로 한다.
- 배포용 패키지: `python scripts/make_release.py` → `dist/website-monitoring-kit-vX.Y.Z.zip`. 허용 목록 방식으로 복사하며, 실제 기관 도메인 등 허용되지 않은 URL이 문서에 섞여 있으면 중단한다.
- 키트 갱신(`core/`, `scripts/` 교체)은 `workspace/`를 건드리지 않는다. 설정·프로필 형식이 바뀌면 `VERSION`과 변경 사항을 공지한다.
- 이 저장소의 `workspace/legacy/`는 이전 점검 원본(내부용)이다. 새 배포 저장소에는 `make_release.py` 산출물만 올린다.
